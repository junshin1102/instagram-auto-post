# 毎朝の生存確認

作った自動化システムが**静かに止まっていても気づけない**、という問題を潰すためのものです。

セッション履歴を見ると、未読のまま放置されている作業が13件ありました。
仕組みを作ること自体より、**作った仕組みが動き続けているかを見ること**のほうが
手が回らなくなりがちです。そこを機械にやらせます。

投稿や出品はしません。**見るだけ**です。

## できること

毎朝1回、登録した各システムが「昨日ちゃんと動いたか」を確認して、LINEに1通だけ送ります。

```
🔴 自動化システム 2/6件 に問題があります
(09/13 07:30 時点)

✅ Instagram自動投稿
　 11時間前に実行(media_id=18111 スライドショー(10枚))
❌ ヤフオク自動出品
　 35日前から動いていません(最後: posted)
✅ ラベル発行
　 5時間前に更新
❌ 各EC監視システム
　 3時間前にエラー: RuntimeError: アクセストークンの有効期限切れ
✅ 集荷自動化
　 8時間前に更新
✅ 全EC売上レポート
　 2時間前にコミット
```

全部正常なら `🟢 自動化システム 全6件 正常` の1行で終わります。
**異常がある日だけ中身を読めばよい**状態になります。

## 準備

### 1. 設定ファイルを作る

```
python health_check.py --init
```

`checks.json` ができるので、`path` を実際のフォルダに書き換えてください。

確認方法は3種類あります。システムの作りに合わせて選びます。

| type | 見るもの | 向いているケース |
|---|---|---|
| `heartbeat` | `state/heartbeat.json` | `post_to_instagram.py` のように実行記録を書く仕組み |
| `file_mtime` | ファイルの更新時刻 | ログファイルを吐く仕組み |
| `git_commit` | 最終コミット時刻 | 結果をgitに記録する仕組み |

`max_age_hours` は「これより古かったら異常とみなす」時間です。
1日1回動くものなら30時間くらいが目安です。

### 2. 試す(LINEには送らない)

```
python health_check.py --dry-run
```

### 3. 毎朝動かす

`LINE_CHANNEL_ACCESS_TOKEN` を環境変数に設定した上で、管理者PowerShellで1回だけ:

```
schtasks /create /tn "JunshinHealthCheck" /tr "C:\path\to\run_health_check.bat" /sc daily /st 07:30
```

## Codexに任せる場合

このスクリプトは、異常が1件でもあれば**終了コード1**を返します。
そのままCodexに渡せば、異常時だけ調査させられます。

Codexへの指示文の例:

```
毎朝、次を実行してください。

  python C:\path\to\health_check.py

終了コードが0なら、何もせず終了してください。報告も不要です。

終了コードが1の場合のみ、❌ が付いたシステムについて次を調べてください。
  1. そのフォルダのログファイルの末尾100行
  2. エラーメッセージが出ていれば、その原因
  3. 直せるなら直す。ただし以下は勝手にやらないこと:
     - APIキーやトークンの再発行
     - 出品・投稿・削除など、外部に影響が出る操作
     - 30行を超える変更

調べた結果を、原因と対処を3行以内にまとめて報告してください。
直せなかった場合は、何が分からなかったかを書いてください。
```

**キーの再発行と、外部に出る操作は必ず人の判断を挟んでください。**
止まっているものを黙って動かし直すと、二重投稿や二重出品が起きます。

## 補足

`health_check.py` 自体が動かなくなったら本末転倒なので、`last_result.json` に
毎回の結果が残ります。これも `file_mtime` で見張っておくと確実です。
